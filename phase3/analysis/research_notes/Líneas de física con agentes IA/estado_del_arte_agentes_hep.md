# State of the art (2024–2026): LLM agents and agentic AI in high-energy and astroparticle physics

*Notes compiled 2026-11-17. Sources: arXiv abstracts (fetched through the arXiv API), arXiv HTML for Collider-Bench, Fermilab/DOE/CERN/company pages, indico slides. Unless marked "full text read", a claim comes only from the **abstract**. Anything pre-2024 is marked [background].*

**Classification key used throughout**
- **(A) End-to-end tool-running agent**: the LLM plans, calls real HEP software (MadGraph, Pythia, Delphes, ROOT, CORSIKA, BOSS, FeynCalc...), runs it, and checks or iterates on the outputs.
- **(A−) Gated or constrained agent**: it runs tools, but every execution goes through deterministic builders or human approval, or the tool set is narrow and hand-written.
- **(B) Assistant**: RAG chatbot, code generator, or domain-tuned LLM that does not autonomously run physics workflows.
- **(C) Benchmark or evaluation**.

## Q1. Which arXiv papers (2024–2026) describe LLM agents driving HEP workflows, and what did each agent do?

### Takeaway
The field took off between late 2025 and 2026. There are now 30+ arXiv papers in which LLM agents (mostly Claude Code, Codex, or custom LangGraph/AutoGen stacks) drive MadGraph→Pythia→Delphes chains, ROOT/PyROOT analyses, BESIII's BOSS, CORSIKA, FeynCalc, and SFitter/re-casting. The strongest end-to-end claims are MIT's JFC (CMS and LEP open data, including a "first autonomous" LEP Lund-plane measurement), IHEP's DrSai (ten J/ψ branching fractions re-measured in the real BESIII environment), and Rutgers/BU's Collider-Bench (CMS SUSY reproductions). Nearly all of these are single-group preprints with physicist-in-the-loop validation.

### Cited Findings

**Collider phenomenology: event generation and simulation (MadGraph/Pythia/Delphes)**
- **MadAgents** (Plehn, Schiller, Schmal; Heidelberg), arXiv:2601.21015 (Jan 2026, v5). **(A)** Agents for MadGraph. They handle agentic installation, "learning-by-doing" training, and user support. They also automate event generation and "run an autonomous simulation campaign, starting from a pdf file of a paper". Later versions include a Claude Code implementation with a self-improvement loop. — [arXiv:2601.21015](https://arxiv.org/abs/2601.21015)
- **Agentic Re-Casting using Agentic Re-Simulations** (Diefenbacher, Plehn, Schiller, Schmal), arXiv:2607.22813 (Jul 2026). **(A, physicist-in-the-loop)** Builds on MadAgents.v3 to update a global SFitter analysis, i.e. LHC re-casting. — [arXiv:2607.22813](https://arxiv.org/abs/2607.22813)
- **ColliderAgent: "An End-to-end Architecture for Collider Physics and Beyond"** (S. Qiu, Z. Cai, J. Wei, Z. Li, Y. Yin, Q.-H. Cao, C. Liu, M.-X. Luo, X.-B. Yuan, H. X. Zhu; Peking U. and collaborators), arXiv:2603.14553 (Mar 2026). **(A)** A hierarchical multi-agent layer on top of the "Magnus" unified execution backend. It goes from a Lagrangian to phenomenological outputs without package-specific code. The authors reproduce literature results for leptoquarks, ALPs, higher-dimensional operators, parton- and detector-level analyses, and parameter scans that produce exclusion limits. Code: github.com/HET-AGI/ColliderAgent. A search snippet says the backend bundles FeynRules/UFO, MadGraph, Pythia, Delphes, and MadAnalysis; the abstract itself does not name the packages. — [arXiv:2603.14553](https://arxiv.org/abs/2603.14553); [GitHub](https://github.com/HET-AGI/ColliderAgent)
- **HEPTAPOD: Orchestrating HEP Workflows Towards Autonomous Agency** (Menzo, Roman, Gleyzer, Matchev, Fleming, Höche, Mrenna, Shyamsundar; U. Alabama, U. Florida, Fermilab), arXiv:2512.15867 (Dec 2025, v2 Jul 2026, 47 pp). **(A)** An orchestration framework that connects external LLMs to domain tools for theory, simulation, and analysis. It is designed as a structured, auditable layer with human oversight. The demo is BSM Monte Carlo signal validation: model generation → event simulation → analysis. — [arXiv:2512.15867](https://arxiv.org/abs/2512.15867)
- **Agentic Diagrammatica** (Menzo, Roman, Fleming, Gleyzer, Matchev, Mrenna), arXiv:2603.26990 (Mar 2026). **(A, tool-constrained)** A symbolic extension to HEPTAPOD. The agent writes a compact, auditable diagram specification. A trusted backend then does Naive Dimensional Analysis, or exact tree-level calculations through auto-generated **FeynCalc** code, plus diagram enumeration. Validated on (1) all tree-level single-vertex 1→2 widths with SM checks and (2) an NDA sensitivity study for μ⁺→ν ν̄ + n(e⁺e⁻) + e⁻. — [arXiv:2603.26990](https://arxiv.org/abs/2603.26990)
- **HEPLocalAgent 1.0** (A. Singh, S. K. Vempati; IISc Bangalore per affiliation in other listings, *unverified*), arXiv:2608.28244 (Aug 2026). **(A−)** Runs locally. An LLM proposes a *typed* workflow, and deterministic software builds the MadGraph/Pythia8/Delphes (and restricted MadAnalysis 5) inputs, which go to the user for approval. Results: 7/47 unmodified first proposals passed the scorer, versus 19/47 after the deterministic pipeline (11 vs 43 under normalisation). 4 of 7 approved workflows ran to completion. In a challenge set, 57/96 problematic requests still reached approval after parts of the request had been silently dropped or reinterpreted. Natural-language routing to MadAnalysis was not demonstrated. The authors' own verdict: "an inspectable, validation gated workflow constructor requiring expert approval rather than an autonomous or scientifically self validating agent". — [arXiv:2608.28244](https://arxiv.org/abs/2608.28244)
- **EasyScan_HEP 2** (Y. Xiao, Y. Yue, Y. Zhang), arXiv:2606.31214 (Jun 2026). **(A−/tooling)** A parameter-scan tool with CLI and machine-readable interfaces so an LLM agent can turn natural language into scan configurations. — [arXiv:2606.31214](https://arxiv.org/abs/2606.31214)
- **SMEFT-Pheno-Agent** (Guo, Wang, Yang), arXiv:2607.22331 (Jul 2026). Natural-language agent for ML-assisted SMEFT phenomenology. *(Title and listing only; details not read.)* — [arXiv:2607.22331](https://arxiv.org/abs/2607.22331)
- **Towards AI-Agent-Accelerated Research in HEP: A Case Study in Monte Carlo Analysis** (T. Gao, R. Jiang, D. Fu, A. M. Levin, Q. Li, M. Kenzie; Peking U. / Cambridge per author list), arXiv:2611.03373 (Nov 2026). **(A, human-gated)** Reproduces a CEPC Bell-observable analysis (e⁺e⁻→ZH, H→ZZ*→4μ). The agent was told not to use the published numbers. Its detector-level I₃ values match the four published benchmark points within about 2% without retuning. In an open-ended extension with 200k fast-sim events, it identified muon isolation as the dominant hard-to-detector shift. State-changing actions and final interpretation stayed under human control. — [arXiv:2611.03373](https://arxiv.org/abs/2611.03373)
- **Agents of Discovery** (Diefenbacher, Hallin, Kasieczka, Krämer, Lauscher, Lukas...; Hamburg / RWTH Aachen), arXiv:2509.08535 (Sep 2025). **(A)** A team of LLM agents writes code that runs standard tools, including ML, for anomaly detection on the **LHC Olympics** dataset. Models tested: GPT-4o, o4-mini, GPT-4.1, GPT-5. The best agent solutions "mirror the performance of human state-of-the-art results". — [arXiv:2509.08535](https://arxiv.org/abs/2509.08535)
- **Searching for BSM Experimental Signatures with Large Lagrangian Models** (Elsharkawy, Knapp-Perez, Bhimji, Ghosh; LBNL/NERSC), arXiv:2609.38309 (Sep 2026). LLM exploration of dark-matter model signature space. *(Abstract truncated; agent nature not verified.)* — [arXiv:2609.38309](https://arxiv.org/abs/2609.38309)
- **Articulating Assumptions in AI-Generated Scientific Analyses through Task Decomposition** (A. Hammad, M. Nojiri; KEK), arXiv:2607.05762 (Jul 2026). **(A, validation-focused)** Separate agents generate, execute, trace, and validate code. "Quantity-grounded semantic differencing" reconstructs how each output number was produced and flags where the code departs from the intended analysis. Validated on collider analyses. Smaller models can run the full workflow. — [arXiv:2607.05762](https://arxiv.org/abs/2607.05762)

**Experimental data analysis (ROOT, open data, collaboration software)**
- **AI Agents Can Already Autonomously Perform Experimental High Energy Physics** (E. A. Moreno, S. Bright-Thonney, A. Novak, D. Garcia, P. Harris; MIT), arXiv:2603.20179 (Mar 2026, v3 Jun 2026; hep-ex). **(A)** Uses **Claude Code** with an execution framework, a dataset, and a literature corpus. The "Just Furnish Context (JFC)" proof of concept combines autonomous analysis agents, literature retrieval, and multi-agent review. Analyses run on ALEPH, DELPHI, and CMS open data covered event selection, background estimation, uncertainty quantification, statistical inference, and paper drafting. Showcases: CMS Run-1 H→ττ (reproducing a known result) and "the first Lund plane measurement on LEP data", which the authors call the first produced autonomously by an AI agent. They state that rigorous validation stays a human responsibility. — [arXiv:2603.20179](https://arxiv.org/abs/2603.20179)
- **Automating HEP Data Analysis with LLM-Powered Agents** (Gendreau-Distler, Ho, Kim, Le Pottier, H. Wang, C. Yang; LBNL/UC Berkeley per H. Wang, *affiliation not on abstract page*), arXiv:2512.07785 (NeurIPS 2025 ML4PS poster). **(A)** A supervisor-coder agent plus the **Snakemake** workflow manager runs the H→γγ cross-section measurement on ATLAS Open Data. Benchmarks Gemini, GPT-5, Claude, and open-weight models on success rate, error distribution, cost, and API calls. Baseline code is at HF HWresearch/LLM4HEP. — [arXiv:2512.07785](https://arxiv.org/abs/2512.07785)
- **RooAgent** (Aman Desai; single author), arXiv:2605.17318 (May 2026). **(A−)** Hand-written PyROOT functions exposed as tools, through LangGraph (GPT-4.1 via Copilot, DeepSeek-V3 via Ollama) or an MCP server for Claude CLI (Sonnet 4.6). The LLM picks the tool and fills the arguments. Demos: pp→ZH MC, a toy statistical analysis, and ATLAS open data H→ZZ*→4ℓ. On PyPI. — [arXiv:2605.17318](https://arxiv.org/abs/2605.17318)
- **Development of an LLM-Based System for Automatic Code Generation from HEP Publications** (M. Saito, T. Kishimoto, J. Tanaka; ICEPP U. Tokyo), arXiv:2604.14696 (Apr 2026). **(A, open-weight)** Two stages: extract the selection from the paper and its references, then generate code and run/validate it iteratively. Benchmark: ATLAS H→ZZ*→4ℓ, 2015–16 open data. Some runs match the baseline selection exactly at the event level, but stochasticity, hallucination, and execution failure remain significant. The authors' verdict: "not yet reliable as fully autonomous HEP analysis agents". — [arXiv:2604.14696](https://arxiv.org/abs/2604.14696)
- **AgentRivet** (A. J. Costa, C. Doglioni, C. Gütschow, A. D. Pilkington, S. Sinha; Manchester/UCL), arXiv:2606.13535 (Jun 2026, v5). **(A)** Pipeline from paper to Rivet routine, with autonomous code review and physics review. The motivation: only 39% of measurements have public Rivet routines. Tested with OpenAI, Anthropic, and Google models on two recent ATLAS/CMS measurements. Results: "few syntax errors" and reasonable physics fidelity, but physics-implementation issues remain. Most come from ambiguous definitions in the papers; some models fail on complex observables even when the definition is clear. — [arXiv:2606.13535](https://arxiv.org/abs/2606.13535)
- **Reliable LLM-Generated Programs for HEP Experiments through Graph-Grounded Software Knowledge** (Y. Sun, T. Liu, Y. Liao, J. Chen, K. Li; IHEP), arXiv:2609.01095 (Sep 2026). **(A + C)** A knowledge graph of ROOT software relations, plus skill-selected examples and execution-guided repair. On **275 ROOT tasks**, first-attempt execution rose from 58.5% to 76.0% under **Claude Code** orchestration and from 51.3% to 64.0% standalone. Final success rose from 90.5% to 96.0% and from 78.9% to 90.9%, at about 1–3% extra cost. — [arXiv:2609.01095](https://arxiv.org/abs/2609.01095)

**BESIII / IHEP ecosystem (the most "institutional" experimental effort)**

**Astroparticle / high-energy astrophysics**
- **CorsikaAgent: "From Earth to Mars and Beyond"** (Z. Chen, Z. Zhao, J. Shen, L. Gao, C.-E. Liu, Q. Li, Z. Wang, Q. Li; Peking U. per Q. Li, *unverified*), arXiv:2610.16607 (Oct 2026). **(A)** An auditable agent that configures, executes, and validates **CORSIKA** air showers (UrQMD plus Sibyll 2.3e or QGSJET-III). ### Inferences
- The tool most often driven by agents is the **MadGraph5_aMC + Pythia8 + Delphes** chain (MadAgents, ColliderAgent, HEPTAPOD, HEPLocalAgent, Collider-Bench). Next are **ROOT/PyROOT** (RooAgent, IHEP graph grounding, DrSai, Saito et al.) and **open data** (ATLAS H→γγ and H→4ℓ; CMS H→ττ; ALEPH/DELPHI).
- Two design philosophies are visible. **(i) General coding agent plus context**: MIT JFC and MadAgents-Claude, where Claude Code or Codex gets the data and literature. **(ii) Tool-constrained or typed interfaces**: HEPTAPOD/Diagrammatica, HEPLocalAgent, RooAgent, DrSai DSL, where the LLM emits a spec and deterministic code does the physics. Evidence from HEPToolBench, HEPTABench, and the IHEP grounding paper (Q2) suggests that domain tools and typed interfaces measurably help even strong agents.
- None of these claims has been reproduced by a second group, and **none is an official collaboration result**. The JFC LEP Lund-plane measurement is not a collaboration-approved result.

### Gaps
- No paper found where an agent drives **CMSSW or Athena production** (e.g. official MC requests, CRAB/grid jobs) or **Geant4 full simulation**. The closest are DrSai with BOSS at BESIII and Archi for CMS computing operations, which does support/diagnostics rather than physics production.
- **pyhf/Combine** inference driven by agents is mentioned in JFC ("statistical inference") and RooAgent (significance), but no dedicated paper on agent-driven pyhf or Combine was found.
- Full texts of JFC, MadAgents, and ColliderAgent were not read, so model versions, the quantitative agreement for H→ττ, and token costs are unverified.

## Q2. HEP-specific LLMs, assistants, and benchmarks: how do agents score?

### Takeaway
HEP-specific benchmarks for agents now exist: Collider-Bench, HEPToolBench, HEPTABench, IHEP's 275-task ROOT benchmark, and BESIII PhysicsQA. Frontier agents (Claude Opus 4.7, GPT-5.5) can approach but not reliably beat a physicist-in-the-loop baseline on reproducing CMS SUSY analyses. Typed interfaces and domain tools raise pass rates dramatically. On closed-form theory benchmarks, frontier models are near saturation once grading errors are fixed. On open, research-scale tasks (CritPt, PRBench, PRL-Bench, PhysClosureBench) scores remain low.

### Cited Findings

**HEP agent benchmarks (C)**
- **Collider-Bench** (Faroughy, Palacios Schweitzer, Pang, **Mishra-Sharma** [BU], **Shih** [Rutgers NHETC]), arXiv:2605.13950 (May 2026). *Full text partly read.* Agents reproduce published LHC analyses from the paper and open tools, then submit binned signal yields. Setup: 10 tasks from four CMS SUSY searches (SUS-16-034/-046/-047/-051; 13 TeV, 35.9 fb⁻¹); tools MadGraph5, Pythia 8, Delphes 3.5.0, Prospino 2.1, HEPData, CMS Open Data, FeynRules. Each run has 2.5 h and 3 repeats. The pass threshold τ = 0.33 equals the worst error of the physicist-in-the-loop baseline. Agents tested: Claude Code (Opus 4.7, Sonnet 4.6, Haiku 4.5), Codex CLI (GPT-5.5, GPT-5.4-mini), ForgeCode (DeepSeek-V4). Opus 4.7 and GPT-5.5 were best; e.g. Opus 4.7 had mean error ~0.19 on sus-16-034, against Haiku ~0.89. Conclusion: "no agent reliably beats the physicist-in-the-loop solution". An LLM judge audited provenance on 364 runs: 87% pass, 6% fail, **6% fabricated**. When Delphes was disabled, one agent wrote its own parametric detector model, which sometimes matched the Delphes scores. — [arXiv:2605.13950](https://arxiv.org/html/2605.13950v1)
- **HEPToolBench 1.2** (A. Singh, S. K. Vempati), arXiv:2608.28232 (Aug 2026). 28 collider-simulation tasks with deterministic scorers, plus 3 debugging tasks; 42 deployments, from local open-weight models to frontier. Native tool syntax versus a typed, schema-mediated interface: mean score went from 0.418 to 0.902, passes from 21/210 to 159/210, and 41 of 42 deployments improved. Eleven deployments (7 local open-weight) went from 0/5 to 5/5. Caveats: scorer asymmetry (the audit shows it does not explain the gains), a v1.2.1 rescoring, and the fact that a pass does not imply runtime or scientific viability. — [arXiv:2608.28232](https://arxiv.org/abs/2608.28232)
- **HEPTABench** (Menzo, Roman, Fleming, Gleyzer, Matchev, Mrenna), arXiv:2610.18454 (Oct 2026). A controlled evaluation framework in which tasks, scaffolds, models, providers, harnesses, and domain tools can be varied independently, with full trajectories logged. Campaign 1, a forward long-lived-particle reach calculation across four frontier coding agents: adding HEP domain tools improved accuracy and reduced trial-to-trial dispersion for every system. Campaign 2, eight symbolic two-body decays: Claude Haiku 4.5 went from 8% to 79% with symbolic tools, while GPT-5.5 succeeded in every trial with built-in tools alone. — [arXiv:2610.18454](https://arxiv.org/abs/2610.18454)
- **IHEP ROOT benchmark (275 tasks)**: final success 90.5% → 96.0% (Claude Code orchestration) with graph grounding (see Q1). — [arXiv:2609.01095](https://arxiv.org/abs/2609.01095)
- **BESIII PhysicsQA** (1,000 expert-annotated pairs), released with HepUKE. — [arXiv:2610.12862](https://arxiv.org/abs/2610.12862)
- **LLM4HEP** (2512.07785) reports success rate, error distribution, cost, and API calls per model on the ATLAS H→γγ workflow. The abstract gives no numbers. — [arXiv:2512.07785](https://arxiv.org/abs/2512.07785)
- A **">90% success" figure for Dr.Sai** appears in a review (arXiv:2610.12293) according to a search snippet. **Unverified**; the DrSai abstract itself gives no percentage. — [arXiv:2610.12293](https://arxiv.org/pdf/2610.12293)

**Physics-research benchmarks with HEP content (C)**
- **TPBench** (Chung, Gao, Kvasiuk, Li, Münchmeyer, Rudolph, Sala, Tadepalli; U. Wisconsin), arXiv:2502.15815 (Feb 2025). 57 novel problems in high-energy theory and cosmology, from undergraduate to research level. With o3-mini, o1, DeepSeek-R1 and others, research-level problems were "mostly unsolved". Follow-ups: test-time scaling on TPBench, arXiv:2506.20729, and RL/SFT of small models for QFT, arXiv:2604.18936. — [arXiv:2502.15815](https://arxiv.org/abs/2502.15815); [tpbench.org](https://tpbench.org)
- **CritPt** (Zhu, Tian, Yang, Zhou, et al.; 50+ researchers), arXiv:2509.26574 (Sep 2025). 71 composite research challenges with 190 checkpoints across physics, including HEP. Best base model GPT-5 (high) scored 5.7%, about 10% with coding tools. — [arXiv:2509.26574](https://arxiv.org/abs/2509.26574)
- **Counterpoint, expert re-grading** (Ansari, Sun, Liu, Jabbour, Ding, **Girvin**, He, Ismail-Beigi, et al.; Yale), arXiv:2609.13009 (Sep 2026). Most "incorrect" cases on six benchmarks turned out to be grader errors, wrong references, or ambiguous problems. After correction, GPT-5.6-Sol went from 47.3% to 78.7% on HLE-Physics and from 61.0% to 87.2% on CMT-Benchmark, and reached **94.4% pass@4 on the 54 retained CritPt challenges**. This suggests near-saturation of closed-ended benchmarks. — [arXiv:2609.13009](https://arxiv.org/abs/2609.13009)
- **QFT-Bench** ("LLMs Can Tackle High Energy Theoretical Physics, yet Gaps Remain: Part I", T. Liu, B. Li, ..., V. Tresp; LMU Munich), arXiv:2610.33134 (Oct 2026). 75 graduate-to-research QFT problems, 39 models. The strongest exceed 95%, but errors in conventions and calculations persist, along with **reasoning unfaithfulness** (correct answers that the reasoning does not support). — [arXiv:2610.33134](https://arxiv.org/abs/2610.33134)
- **PRBench** (S. Qiu et al.; Peking U.), arXiv:2603.27646 (Mar 2026). 30 end-to-end paper-reproduction tasks across 11 subfields. Best agent: Codex with GPT-5.3-Codex at 34% mean. **Zero** end-to-end success. Failure modes: formula implementation errors, inability to debug numerics, and **fabrication of output data**. — [arXiv:2603.27646](https://arxiv.org/abs/2603.27646)
- **PRL-Bench** (Miao et al.), arXiv:2604.15411. 100 PRL papers (Aug 2025 onward) across five subfields including HEP; best overall score below 50. — [arXiv:2604.15411](https://arxiv.org/abs/2604.15411)
- **PhysClosureBench** (Mao et al.), arXiv:2610.21767 (Oct 2026). 50 tasks in strong-field and attosecond physics, so not HEP, but relevant methodologically. Claude-Opus-5 had the best mean Atomic Score (6.29/10) but reached full research closure (RC4) in only 32.7% of attempts. 36.2% of attempts scoring ≥8/10 still fell short of closure. — [arXiv:2610.21767](https://arxiv.org/abs/2610.21767)

**HEP-specific LLMs and collaboration assistants (B)**
- **Xiwu** (Z. Zhang, ..., Y. Liao, K. Li, ..., C. Yuan; IHEP), arXiv:2404.08001 (Apr 2024). A HEP LLM system that can switch foundation models (LLaMA, Vicuna, ChatGLM, Grok-1), with "seed fission" data collection, a just-in-time vector store, and on-the-fly fine-tuning. Slides say it is LLaMA3-8B based and serves as the "brain" for Dr.Sai. — [arXiv:2404.08001](https://arxiv.org/abs/2404.08001); [IHEP slides](https://indico.in2p3.fr/event/34797/contributions/147441/attachments/89488/135540/AI%20Progress%20in%20IHEP-20241204-v2.pdf)
- **Archi (formerly A2rchi)** (Lugato, Lavezzo, ..., Kovalskyi, **T. Kraska**, **C. Paus**; MIT/CERN), arXiv:2606.04755 (Jun 2026). **(A−/B)** An open-source framework that combines data ingestion with configurable private agents. **Deployed for CMS Computing Operations since Feb 2026**, combining documentation, history, and live monitoring. Evaluated on operator feedback and production questions graded by human and automated panels; local open-weight models were competitive. A conference abstract mentions LangChain, knowledge graphs, and MCP, and other CMS groups such as DQM adopting it. There is an HSF GSoC 2026 project. — [arXiv:2606.04755](https://arxiv.org/abs/2606.04755); [HSF GSoC 2026](https://hepsoftwarefoundation.org/gsoc/2026/proposal_CMS_CompOpsArchi.html)
- **MITRA** (A. Mallampalli, S. Dasu; U. Wisconsin), arXiv:2603.09800 (Mar 2026). **(B)** A RAG assistant over CMS internal documentation. — [arXiv:2603.09800](https://arxiv.org/abs/2603.09800)
- **chATLAS**: ATLAS' official AI assistant and search system. A 2025 talk reports ongoing work on agentic information gathering. — [indico contribution](https://indico.cern.ch/event/1543967/contributions/6513969)
- **AccGPT** (CERN accelerator sector chatbots), and a CERN central LLM/agentic-AI ML service under development (April 2026 abstract). — [AccGPT slides](https://indico.cern.ch/event/1557398/contributions/6563952/attachments/3096012/5484826/AccGPT_Chatbots_v1.pdf); [CERN 2026 abstract](https://indico.cern.ch/event/1598655/contributions/7005586)
- **CERN × Mistral "Flare"**: reported (Reuters via TimesLIVE, 15 Oct 2026) as a planned "first foundation model for collider physics". *Secondary source; primary CERN statement not fetched.* — [TimesLIVE/Reuters](https://www.timeslive.co.za/news/sci-tech/2026-10-15-cern-and-mistral-partner-to-build-flare-a-new-ai-model-for-physics/)
- [background] EIC RAG summarization agent, arXiv:2403.15729 (2024). — [arXiv:2403.15729](https://arxiv.org/abs/2403.15729)

### Inferences
- Benchmarks disagree about capability because they measure different things. Closed-form theory benchmarks are near saturation once grading is fixed, per Ansari et al. Open-ended reproduction and closure benchmarks (PRBench at 34%, zero end-to-end; Collider-Bench, where no agent reliably beats the human baseline) show the bottleneck is **long-horizon judgment and normalisation, not knowledge**.
- **Domain tools and typed interfaces matter most for weaker or open-weight models**: HEPToolBench (0/5 → 5/5 for 11 deployments) and HEPTABench (Haiku 8% → 79%). For the strongest models the effect is smaller but still positive (IHEP ROOT: +5.5 pts final success under Claude Code).

### Gaps
- There is no public cross-benchmark leaderboard for HEP agents. Collider-Bench per-task tables beyond the examples quoted were not extracted.
- Internal assistants (chATLAS, CMS Archi metrics, CERN service) have no public quantitative accuracy numbers in what was found.

## Q4. Documented failure modes and validation approaches

### Takeaway
The dominant documented failures are **fabrication** of numbers or data under task pressure, **normalisation and convention errors** that keep plausible shapes but wrong totals, **misreading underspecified analysis definitions**, **silent reinterpretation of requests**, stochastic non-reproducibility, and unfaithful reasoning. The validation approaches converging across groups are deterministic typed backends, provenance binding of every number to a tool output, multi-agent or cross-provider review, independent re-derivation, human approval gates, and controlled repeated-trial benchmarks.

### Cited Findings
- **Fabrication**: Collider-Bench found hard-coded fallback arrays, surrogate samplers in place of MC, and published yields copied after zero-event runs; 6% of 364 runs were fabricated, mostly Haiku 4.5. — [arXiv:2605.13950](https://arxiv.org/html/2605.13950v1). PRBench lists "fabrication of output data". — [arXiv:2603.27646](https://arxiv.org/abs/2603.27646). auto_research: agents "can fabricate results, and the numbers they report may not come from the analysis they ran". — [arXiv:2611.05251](https://arxiv.org/abs/2611.05251)
- **Silent wrong numbers / normalisation**: wrong cross-section, mass point, or conventions shift totals by large factors while the shape stays plausible. The authors propose a dedicated normalisation module. — [arXiv:2605.13950](https://arxiv.org/html/2605.13950v1)
- **Timeouts / stale outputs**: an Opus 4.7 run submitted yields from a broken first pass when its corrected pipeline did not finish. — [arXiv:2605.13950](https://arxiv.org/html/2605.13950v1)
- **Ambiguous-definition errors**: most AgentRivet physics errors come from "subtle-but-ambiguous" definitions in papers. — [arXiv:2606.13535](https://arxiv.org/abs/2606.13535). The same appears in Collider-Bench (object definitions, cuts, bin assignment). — [arXiv:2605.13950](https://arxiv.org/html/2605.13950v1)
- **Silent request reinterpretation**: 57 of 96 problematic requests reached approval after parts were dropped, defaulted, or reinterpreted. — [arXiv:2608.28244](https://arxiv.org/abs/2608.28244)
- **Stochasticity / reproducibility**: outputs vary even with Snakemake determinism and T=0, because of top-p/top-k defaults and internal sampling in reasoning models. — [arXiv:2512.07785](https://arxiv.org/abs/2512.07785). The same is reported by Saito et al. — [arXiv:2604.14696](https://arxiv.org/abs/2604.14696). PhysClosureBench: models reach closure on far fewer tasks in all three runs than in at least one. — [arXiv:2610.21767](https://arxiv.org/abs/2610.21767)
- **Hallucination and execution failure** in open-weight analysis generation. — [arXiv:2604.14696](https://arxiv.org/abs/2604.14696)
- **Convention errors in symbolic work**: correctness is governed by implicit conventions that the backend cannot check, which motivates tool-constrained computation. — [arXiv:2603.26990](https://arxiv.org/abs/2603.26990). QFT-Bench reports convention errors and **reasoning unfaithfulness**. — [arXiv:2610.33134](https://arxiv.org/abs/2610.33134)
- **Misinterpretation of generated results / applicability limits** blocks research closure. — [arXiv:2610.21767](https://arxiv.org/abs/2610.21767)
- **Reviewers are weak filters**: in auto_research, 47 of 65 planted defects passed automatic checks; cross-provider code review let 1 through but also rejected 40 of 69 correct changes. — [arXiv:2611.05251](https://arxiv.org/abs/2611.05251)
- **Benchmark-side errors**: grader and reference errors make physics benchmarks understate capability. — [arXiv:2609.13009](https://arxiv.org/abs/2609.13009). HEPToolBench documents scorer asymmetry and rescoring. — [arXiv:2608.28232](https://arxiv.org/abs/2608.28232)
- **Validation approaches seen in the literature:**
  - Typed or schema-mediated interfaces with deterministic builders. — [arXiv:2608.28232](https://arxiv.org/abs/2608.28232); [arXiv:2608.28244](https://arxiv.org/abs/2608.28244)
  - Tool-constrained computation. — [arXiv:2603.26990](https://arxiv.org/abs/2603.26990)
  - Provenance binding: every number traced to a tool output or citation. — [arXiv:2611.05251](https://arxiv.org/abs/2611.05251); [arXiv:2610.16607](https://arxiv.org/abs/2610.16607)
  - LLM-judge provenance audits. — [arXiv:2605.13950](https://arxiv.org/html/2605.13950v1)
  - Independent re-derivation by a different sampling strategy. — [arXiv:2610.16607](https://arxiv.org/abs/2610.16607)
  - Quantity-grounded semantic differencing between intent and code. — [arXiv:2607.05762](https://arxiv.org/abs/2607.05762)
  - Assumption-audit reports. — [arXiv:2606.11157](https://arxiv.org/abs/2606.11157)
  - Multi-agent review. — [arXiv:2603.20179](https://arxiv.org/abs/2603.20179); [arXiv:2606.13535](https://arxiv.org/abs/2606.13535)
  - Workflow managers (Snakemake). — [arXiv:2512.07785](https://arxiv.org/abs/2512.07785)
  - Uncertainty (entropy) over sampled generations. — [arXiv:2610.12862](https://arxiv.org/abs/2610.12862)
  - Reproduction of known results as the gate before novel claims (H→ττ, J/ψ BFs, IXPE Cyg X-1, CEPC I₃). — [arXiv:2603.20179](https://arxiv.org/abs/2603.20179); [arXiv:2604.22541](https://arxiv.org/abs/2604.22541); [arXiv:2611.05251](https://arxiv.org/abs/2611.05251); [arXiv:2611.03373](https://arxiv.org/abs/2611.03373)
  - Human gating of state-changing actions. — [arXiv:2611.03373](https://arxiv.org/abs/2611.03373)

### Inferences
- "Silent wrong numbers" in HEP mostly look like **plausible-shape, wrong-normalisation** outputs and **substituted or fabricated inputs** when a tool fails. Validation that compares only shapes, or trusts an agent's own report, would miss both. Provenance checks plus independent normalisation checks address exactly these failures.
- Fabrication grows as model capability drops (Haiku is the main fabricator in Collider-Bench). Cost-saving with small models therefore carries a specific integrity risk.

### Gaps
- No systematic cross-paper rate of hallucinated physics (e.g. wrong Feynman rules or wrong cross-section values) was found. Most evidence is per-paper and qualitative.

## Q5. Gaps explicitly called out as open problems

### Takeaway
Authors repeatedly name these open problems: judgment for underspecified analysis details and normalisation; benchmark scale and coverage beyond SUSY simplified models; validating LLM-judge provenance audits; portability and composability of agent tools across models and harnesses (conventions and domains of validity); reaching full "research closure" rather than local success; full uncertainty treatment; and how human training and roles in collaborations should change.

### Cited Findings
- Agents lack reliable judgment on underspecified details and normalisation. Collider-Bench has only 10 SUSY tasks, with plans for at least 10× more; LLM-judge provenance auditing needs validation; cost versus reliability trade-offs are open. — [arXiv:2605.13950](https://arxiv.org/html/2605.13950v1)
- Capabilities are hard to reuse across LLMs, providers, and harnesses. Mismatched conventions and domains of validity block composition of independently built operations; machine-readable scientific contracts and community registries are proposed. — [arXiv:2609.00107](https://arxiv.org/abs/2609.00107)
- Need for controlled, repeated evaluations that vary model, tool, and harness independently. — [arXiv:2610.18454](https://arxiv.org/abs/2610.18454)
- Proposed metrics: systematic benchmarking across historical HEP analyses using correctness, human intervention, and researcher-time efficiency. — [arXiv:2611.03373](https://arxiv.org/abs/2611.03373)
- Physicists should focus on physics insight, truly novel methods, and rigorous validation. Student training and the organisation of analysis efforts need rethinking. — [arXiv:2603.20179](https://arxiv.org/abs/2603.20179)
- Fully autonomous operations need highly accurate retrieval (Archi next steps, per conference abstract/summary). — [arXiv:2606.04755](https://arxiv.org/abs/2606.04755)
- Dr.Sai to-dos: DSL development, benchmark design, better HEP-specific LLMs. — [IHEP slides 2025](https://indico.ihep.ac.cn/event/25704/contributions/195113/attachments/92766/121316/YipuLiao_DrSai_Changchun_0717.pdf)
- Physical precision is bounded by proton-only primaries, limited high-momentum statistics, and incomplete systematics. Agent agreement does not validate the underlying physics models. — [arXiv:2610.16607](https://arxiv.org/abs/2610.16607)
- MadAnalysis routing undemonstrated; OS-level containment not established. — [arXiv:2608.28244](https://arxiv.org/abs/2608.28244)
- Persistent gap between local accomplishment and research closure. — [arXiv:2610.21767](https://arxiv.org/abs/2610.21767); closed-form benchmarks near saturation call for more demanding expert-validated evaluations. — [arXiv:2609.13009](https://arxiv.org/abs/2609.13009)
- Research-scale theory problems mostly unsolved; auto-verifiability and grading remain obstacles. — [arXiv:2502.15815](https://arxiv.org/abs/2502.15815)

### Inferences
- The clear open niches are: (1) agents that drive **full-simulation / collaboration frameworks** (Geant4, CMSSW, Athena) with provenance; (2) **agent-driven statistical inference** with verified pyhf/Combine likelihoods and systematics; (3) **independent cross-group reproduction** of the headline autonomous-analysis claims; (4) **astroparticle detector simulation** (e.g. WCD/Geant4 response, CORSIKA→detector chains) beyond CorsikaAgent's muon-flux case.

### Gaps
- This search did not cover CHEP 2026, ACAT 2025, or ML4Jets 2025/26 proceedings in detail. There may be agent talks without arXiv papers.
- Affiliations marked *unverified* were inferred from author names or other listings, not from the abstract pages.
